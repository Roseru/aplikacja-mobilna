## Naprawiona część CI

W pierwotnych przebiegach dodatkowo zawiodło wysyłanie raportów JVM/lint: Gradle zakończył się przed utworzeniem XML. Był to wtórny błąd diagnostyki.

- `tools/android_build.sh` zachowuje połączony stdout/stderr Gradle w `app/build/ci/gradle-build.log`, również przy odmowie zastosowania pluginu i braku XML.
- Test urządzenia zachowuje analogiczny `gradle-device.log`. Istniejący receipt etapu nadal pokazuje `application_tests` i rzeczywisty niezerowy kod wyjścia.
- Oba logi należą do istniejących artefaktów wysyłanych przez `if: always()`. Wczesny błąd Gradle pozostawia plik do wysłania; brak XML nie powoduje wtedy wtórnego błędu „brak plików”.
- `set -euo pipefail` zachowuje błąd Gradle mimo udanego `tee`. Nie dodano retry testów, pomijania testów ani zgody na brak wyników. Agregator nadal wymaga ośmiu rzeczywistych sukcesów.

Weryfikacja Linux: **9 testów harnessu CI PASS, bez pominięć**, w kontenerze bez sieci, z repozytorium tylko do odczytu. Nowe przypadki sprawdzają odmowę konfiguracji przed XML, zapis obu strumieni i zachowanie exit23 w obu skryptach. Kontrolują też brak automatycznego ponowienia i brak fikcyjnych raportów. Ruff lint/format i diff-check PASS. Zdalne CI nowego head oraz późniejszego main mają własne wyniki.

## Przekazanie O1 / O3-059

1. PR81 i PR82 pozostają zablokowanymi propozycjami aktualizacji. Nie wyłączać metadanych AAR, nie podnosić samego numeru SDK bez narzędzi i nie zastępować ich kontrolami z main.
2. **O1:** po uporządkowaniu kolejki PR61→64→73→96→105 przygotować jeden spójny etap migracji z aktualnego main. Odczytać oba wskazane head/logi i dobrać pełną macierz Kotlin/Compose compiler/KSP/Room/AGP/Gradle. Dla proponowanego BOM obowiązują SDK37 i minimum narzędzi wskazane wyżej. AGP9 ma także [zmiany integracji Kotlin i DSL](https://developer.android.com/build/releases/agp-9-0-0-release-notes); nie traktować go jako samej podmiany wersji w TOML.
3. **O1:** sprawdzić kompilację, lint, JVM, wszystkie testy urządzenia, migracje/otwieranie istniejącej Room, zachowanie dziennika i outbox oraz formularze po aktualizacji Compose. CompileSdk i targetSdk są oddzielnymi ustawieniami; zmiana targetSdk lub minimum urządzeń wymaga osobnego uzasadnienia.
4. **O3 po zamrożeniu macierzy:** dołączyć wymagane SDK/build tools w obu zadaniach CI, sprawdzić wrapper wraz z oficjalnym SHA-256 dystrybucji, oznaczyć rzeczywiste artefakty i odebrać osiem kontroli oraz osobny main. Do tego czasu pozostaje odebrany zestaw AGP8.9.2/Gradle8.11.1/compileSdk35.
5. Po przyjęciu wspólnej migracji rozliczyć lub zamknąć zastąpione PR-y Dependabot. Sama niniejsza diagnoza ani poprawa logowania nie zalicza nowych bibliotek i nie zamyka tych PR-ów.

O2 nie musi zmieniać API lub schematu serwera dla naprawy diagnostyki. O3-050/051/052 i odbiór prawdziwego APK/API pozostają osobnymi zadaniami.
