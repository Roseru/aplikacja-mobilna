# Decyzje v1 E6 - osoba 2

Status: decyzje przed implementacją, 11 października 2026. Źródłem jest [master E6](../MASTER_PROMPT_E6.md) z main a5da8307. Testy i odbiór będą raportowane osobno; nie jest to PASS.

Publikacja wskazuje własny draft_id i draft_revision oraz osobno zatwierdzone publiczne metadata: source_kind, source_description, aliases, identity (brand, variant, composition), opcjonalną porcję i jawny selected_product exact ref. Serwer nie przyjmuje autora, ról ani statusu official. Nie zmienia szkicu. Identity rozróżnia known/unknown/not_applicable; composition nie dopuszcza not_applicable. Brak energii/składu daje manual_candidates, również przy pustej liście. Świadoma nowa publikacja niekompletnego wpisu pozostaje dozwolona. Pełne przykłady i normatywne DTO powstają przed odpowiednimi endpointami.

Wspólny CatalogState(id=1) ma monotoniczną revision oraz queue_revision. Publikacja, feedback, moderacja, purge i aktywacja official blokują go po koncie aktora. Odczyt strony bierze blokadę współdzieloną; matching po uzyskaniu blokady ponownie odczytuje katalog. Eksport i I/O official pozostają poza tą krótką fazą aktywacji. Domyślna izolacja READ COMMITTED. Produkty blokujemy w porządku UUID; brak blokad cudzych kont przy merge.

Nie zmieniamy ProductDTO, ProductDraft/sync-v1 ani historycznych exact refs. Nowe community_products przechowuje bieżący stan, community_versions niezmienne publiczne metadata konkretnego shared ProductVersion. Współdzielone versions/sources zapisuje wyłącznie wąska SECURITY DEFINER, która nie modyfikuje official. Publiczny DTO nie zawiera konta ani szkicu. Autorstwo i publication binding są prywatne. Skład i wariant tożsamości pozostają osobne od kompletności czterech makr.

NFKC, casefold i normalizacja białych znaków zachowują oryginały. pg_trgm jest selektorem kandydatów, a pełny ograniczony SQL predykat wysokiej zgodności rozstrzyga publikację bez fałszywego braku po truncation. Decimal i g/ml porównujemy dokładnie przez przemnożenie stron; nie używamy float. Porcja nie tworzy odrębnej tożsamości.

Każda mutacja ma UUID Idempotency-Key i X-Sync-Epoch. Kolejność: aktualna rola/JWT, active account/generation, epoka, hash i replay. Osobny E6Receipt przechowuje minimalny wynik i refs; wynik pełny minimum60dni, minimalny hash/potwierdzenie do purge. execute_mutation ma caller-owned session, savepoint efektu i utrwalanie przewidywalnej odmowy po rollback savepointu. Admission receipt poprzedza zapis (1000/dobę); produkty20, zgłoszenia50, głosy200. Replay nie ponawia efektu/quota/audit i nie ujawnia ukrytego payloadu. 429 nie tworzy receipt ponad pulę.

Głos ma własną rewizję/tombstone, parser If-Match dopuszcza0. Feedback liczy oddzielnie plus/minus/voters/is_mine. Merge nie przenosi głosów source; dezaktywuje je i samogłosy całej grupy autorów na target. Zgłoszenia zachowują original exact ref, canonical jest rozwiązywany na odczycie. Moderator wymaga user oraz catalog_moderator/admin w poprawnym kliencie. Zmiana community danych tworzy nową niezmienną wersję, stan ma oddzielną rewizję; verified wymaga pełnych makr i potwierdzenia źródła/wersji. Official można zgłaszać/przekazywać administratorowi, ale nie PATCH/merge sealed official.

Merge atomowo sprawdza oczekiwane wersje obu widocznych roots i potwierdzenie tożsamości. Sprzeczne znane marka/wariant/skład/jednostka dają identity_conflict. Spłaszczenie canonical mapping oraz bounded resolver zapobiegają cyklom i nieograniczonym łańcuchom. Historia posiłków/sync/read/recovery i sealed official nie jest przepinana.

Purge usuwa receipts/binding/votes/osobowe raporty/quota i odłącza author/actor account UUID. Publiczne świadomie zatwierdzone wersje i źródła pozostają dla cudzej historii. Audit nie przechowuje pełnego szkicu, dziennika ani osobowej treści raportu. Downgrade najpierw atomowo odmawia przy dowolnym trwałym artefakcie E6, również w shared tables; pusty downgrade zachowuje graf E4/E5. pg_trgm nie jest usuwane przy cudzych zależnościach.

Podział plików: database jest właścicielem migration/models/ACL/lock/purge/retention/readiness, community repository/service/router/idempotency/tokens, matching schema/matching/wektorów. Root odpowiada za feedback/moderation runtime, main i wygenerowany kontrakt, dokumentację oraz integrację. Niezależny nieautor odbierze całość we własnym checkout/DB.

Ograniczenia: E5-O2-C i APK/Room/WorkManager/HTTPS/restore O1/O3 pozostają otwarte. Bez produkcyjnego wdrożenia, Gemini, billing lub kontaktu z dostawcą. E6-O2 ma jeden własny PR do main, bez merge wykonawcy i bez E7.
Uzgodniony kontrakt wejścia nazywa rewizję szkicu draft_revision; źródło i identity są polami najwyższego poziomu. Composition jest znanym opisem receptury(max4000) albo listą(max100), ewentualnie unknown. DTO używa portion i density(amount,source_description). confirm_new dokumentuje świadomą decyzję publikacji przy brakach/manual; nie omija wielu wysokich zgodności. Community DTO ma jawne płaskie positive_votes, negative_votes, voters i is_mine. Przykłady przed kodem: [publikacja](../../contracts/examples/e6/e6_publish_request.json), [wynik](../../contracts/examples/e6/e6_publish_response.json), [głos](../../contracts/examples/e6/e6_vote_request.json). SQL shared interfaces: lock_community_catalog(shared), bump_community_catalog(queue), admit_community_operation(owner,kind), create_community_version(snapshot,metadata), append_community_audit(event). MutationOutcome pozwala commit odmowy przed emisją HTTP błędu.
