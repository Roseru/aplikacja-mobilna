# Integracja społeczności E6 - osoba 2

Normatywny kontrakt to generowany [backend/openapi.json](../../backend/openapi.json). [Master](../MASTER_PROMPT_E6.md) określa odbiór backendu; formularze, Room, WorkManager i APK wymagają osobnych dowodów O1. Official ProductDTO, pp1, pakiety i ścisły ProductDraft/sync-v1 zachowują dotychczasowy format.

Publikacja działa online. Formularz wybiera własny żywy `draft_id` i `draft_revision`, pokazuje publiczne pola do zatwierdzenia i przyjmuje osobno source_kind (`label`, `recipe`, `estimate`, `ai`), source_description, aliases, identity oraz ewentualną portion/density. [Żądanie](../../contracts/examples/e6/e6_publish_request.json) i [minimalny wynik](../../contracts/examples/e6/e6_publish_response.json) pokazują strukturę. AI opisuje pochodzenie; E6 nie wywołuje modelu. Znana porcja/marka/wariant/gęstość szkicu musi pozostać zgodna. Publikacja nie usuwa szkicu, nie zmienia jego UUID ani payloadu.

`identity.brand/variant/composition` rozróżniają `known`, `unknown` i `not_applicable`; composition nie ma `not_applicable`. Znany skład jest listą do100 pozycji albo recepturą do4000 znaków. Puste pola nie są wildcard. `complete` i `missing_nutrition_fields` dotyczą dokładnie czterech wartości kcal/B/T/W. `missing_identity_fields` jest osobne: znane makra nie dowodzą znanego składu/marki/wariantu. Braki pozostają null, również przy publikacji. Same ml są poprawne bez gęstości; przeliczenie na g wymaga udokumentowanego rho.

`POST /api/v1/products/matches` wymaga JWT/user, własnego szkicu i X-Sync-Epoch. Jest odczytem bez rezerwacji i bez nowego receipt. Wynik to existing_variant/manual_candidates/new_product, maks20 kandydatów z exact refs, powodami i flagą truncated. Brak energii/składu oznacza manual_candidates, również pustą listę. Przy świadomej nowej publikacji z brakami ustaw confirm_new. Wybór selected_product jest decyzją użycia referencji, nie potwierdzeniem zgodności danych szkicu. Nie nadaje autorstwa.

Każda mutacja wymaga UUID Idempotency-Key i X-Sync-Epoch z bootstrapu. Zachowuj klucz oraz niezmienną metodę, path, body i oczekiwane wersje do ACK; lost ACK ponawiaj identycznie. GET ponownie czyta aktualny kontekst konta. Epoka ma pierwszeństwo przed rewizją. Po restore stara epoka daje409 także dla nowego klucza; klient musi uzgodnić lokalne originals/outbox, zamiast automatycznie ponowić publikację/głos/merge.

Publikacja pod blokadą ponownie sprawdza katalog. Jedno wysokie dopasowanie zwraca istniejący wariant, wiele wymaga jawnego wyboru i409. Ten sam draft+revision ma jedno prywatne binding: identyczne metadata/wybór zwracają zapisany ref także pod nowym kluczem, zmienione dają409. Aktualizacja szkicu nie zmienia publicznego snapshotu. Cudzy, usunięty i nieistniejący szkic dają404; stale draft revision409.

`GET /community/products` i `/community/products/{id}?revision=N` mają osobny CommunityProductDTO. Pokazują exact revision, canonical_ref, source_kind/source_description/source_id, jednostki, kompletność, verification/visibility, plus/minus/voters/is_mine. Nie zawierają konta, issuer/sub ani draft_id. Po merge exact GET zachowuje pierwotne makra i identyfikator, ale pokazuje aktualny canonical_ref. Historyczna wersja nie dziedziczy weryfikacji późniejszej korekty. Ukrycie źródła/celu odcina publiczny odczyt; własny posiłek nadal używa utrwalonego snapshotu.

`GET /products/{id}/feedback` obsługuje community i dostępne official. Zwraca positive_votes, negative_votes, voters, my_value, my_revision i is_mine. PUT vote przyjmuje value1 albo-1; DELETE wycofuje głos. If-Match jest cytowaną rewizją **mojego głosu**, np.`"0"` dla braku i `"1"` dla pierwszego głosu. Rewizja produktu/liczników nie zastępuje tej wartości. Głos innej osoby nie powoduje mojego stale write. [Przykład głosu](../../contracts/examples/e6/e6_vote_request.json).

Merge nie przenosi opinii source. Source głosy stają się nieaktywne, target zachowuje swoje poza samogłosami autorów całej scalonej grupy. Użytkownik może świadomie zagłosować na target później, jeśli nie jest autorem. Mutacja starego scalonego ID daje409/product_merged z canonical ref; nie przekierowuj zapisu po cichu. Własny głos daje403/own_product_vote. Rewizje/tombstones pozostają po wycofaniu.

POST reports wskazuje exact product ref zgodny z ID ścieżki, reason i description. Dostępne official również można zgłaszać. Wynik zawiera tylko report_id/revision/status. Moderator z user+catalog_moderator/admin ma bounded kolejkę i jawne resolved/dismissed/referred_to_admin z expected_revision i reason. Official korekta wymaga procesu nowego release administratora; PATCH community nie modyfikuje official.

Strony community używają cp1, kolejka mq1. Token wiąże konto/generację/epokę/query/status/sort/limit/after, wersję oraz początkowy expiry60min. Limit1–500, domyślnie100; query1–100, token≤4096, odpowiedź≤1MiB. W razie catalog_changed/moderation_queue_changed409 rozpocznij listę od nowa. Uszkodzony/cudzy lub parametry zmienione422, expiry410. TTL nie jest przedłużany. Rotacja sekretu unieważnia stare podpisy; nie oznacza zmiany epoki/generacji.

Chronione odpowiedzi i błędy mają Cache-Control:no-store. Publiczne aktualne community pobieraj przez autoryzowany GET; receipt nie zawiera ukrywalnego DTO. Odrębna lokalna historia posiłku pozostaje trwała. Po cleanup pełnej odpowiedzi (minimum60dni) replay daje409/idempotency_result_expired z executed/denied, bez ponownego efektu.

Limity UTC/dobę/konto:20 nowych produktów,50 zgłoszeń,200 zaakceptowanych zmian głosu i1000 nowych receipts (także odmowy/moderacja). Replay nie zużywa ponownie puli.429 ma Retry-After; nie twórz kolejnych kluczy, aby obejść odmowę. Body≤1MiB, JSON depth≤20, aliases≤50; nazwa/marka/wariant/źródło/raport/powód≤2000. Strict extra=forbid odrzuca owner/role/status spoof.

Przed odbiorem O1 należy wykonać realne formularze/caching/session switching i lost ACK na zgodnym APK oraz zachowanie Room/outbox. Python HTTP/PG i testowy Keycloak O2 nie potwierdzają tego odbioru. Pełne E5-O2-C i KO-01–02/30/31 pozostają otwarte.

Poprawny podpisany cp1/mq1 własnego konta po zmianie epoki daje409/sync_epoch_changed, po zmianie generacji409/account_generation_changed. Walidacja podpisu, ścisłego kształtu, właściciela i parametrów poprzedza ten kontekst; epoka poprzedza generację, expiry i wersję katalogu. Cudzy/uszkodzony token lub niezgodne parametry nadal422; rotacja podpisu nadal422, zgodny wygasły410.
